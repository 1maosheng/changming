# 记忆层 v2 · 设计说明

> 状态：L0 已落地（2026-11-20）：`workspace/AGENTS.md`（983 B，引擎自动读）+ 定位卡写实 + `建会话.mjs --bind`；L1 注入、去重、语义检查仍是草案。本文只定义「记忆层怎么组织」，不涉及工程化落地（按钮、自动化、打包）。
> 现有 `docs/记忆约定.md` 是 v1 的规则摘要，v2 通过后应由本文取代其结构部分。
> L0 的落地位置是 `src/workspace/AGENTS.md`（不是 `docs/记忆约定.md`）。

## 一、要解决的四个问题

v1 是「分区制」：按文件切块（§〇 / §一 / §二 / §五 / 共享 / 归档），能防串味，但撑不住规模。

| 缺什么 | 症状 | v2 的解法 |
|---|---|---|
| 类型 | 事实、决策、偏好、教训混在一个 §五，全是自然语言 bullet | 类型码 F/D/P/L/R/C |
| 状态 | 一条记忆没有「还成不成立」，只能靠人记 | active / superseded / archived |
| 读取路径 | 只能整篇读，文件一大开场就爆 | 两级：索引注入（≤30 条）+ 按需检索 |
| 证据 | 结论和猜测同样重量 | 每条带 证据 + 可信度 + 日期 |

一句话判据：**能不能只读 30 行就知道「该拉哪条」**。能，就是记忆层；不能，就还是文件夹。

## 二、五层结构

| 层 | 载体 | 体量 | 何时进上下文 | 只放什么 |
|---|---|---|---|---|
| L0 规则 | `workspace/AGENTS.md`（引擎当 baseline 加载） | ≤1 KB | **每会话一次**（进静态前缀） | 禁止 / 必须，不放知识 |
| L1 交接 | `场景私有记忆.md` 的 §〇 | ≤4 KB | **每会话一次**（建会话时注入） | 当前 / 下一步 / 卡点 / 最近变更 |
| L2 知识 | 同文件 §一 §二 §五 | 整文件 ≤25 KB | 索引注入 + 按需检索 | 条目流（第三节） |
| L3 项目 | `项目记忆/<项目id>.md` | ≤8 KB | 按需 | 项目事实 / 进度 / 阻塞 |
| L4 共享 | `_共享记忆/` 四块板 | 各 ≤4 KB | 按需 | 公告 / 待办 / 事实库 / 索引 |
| L5 冷层 | `归档/<YYYYMM>/` | 不限 | 仅检索 | 可追溯，不注入 |

**成本原则**：L0/L1 是「每会话付一次」的（进静态前缀），所以要极短；L2 以下「按需付费」。**真正贵的不是注入，是改写前缀**——细则见第三节。

目录（以「命令」场景为例，全部 posix 路径）：

```
data/.dsh/场景记忆/
  命令/
    场景私有记忆.md      ← L1 + L2 主体
    身份卡.md            ← 工具生成，禁止手改
    场景画像.md          ← 工具生成，禁止手改
    _文件索引.md         ← 工具生成
    _条目索引.md         ← v2 新增，工具生成
    项目记忆/<项目id>.md  ← L3
    归档/202611/         ← L5
  _共享记忆/             ← L4
```

配套（不在场景记忆目录内）：`src/workspace/AGENTS.md` ← L0 规则，引擎当 baseline 加载。

## 三、注入落点与缓存（前缀分层）

> 实测依据：本会话 337 次请求命中 97.4%（23.09M / 23.70M）。其中一次在 message[1] 的中部插入，输入 93.4K 只命中 12.3K（13.2%），一轮重算 81K；中位命中则是 98.7%。

### 3.1 两条事实

1. **缓存是前缀级的**：第 k 个 token 变了，k 之后全部重算。所以改写已发过内容的代价 = 它后面的一切。
2. **「新内容」≠「失效」**：尾部追加只付增量（每轮约 1K），中部改写付全量（可达 80K）。

### 3.2 前缀布局（稳定性递减）

| 段 | 内容 | 变化频率 | 计费 |
|---|---|---|---|
| P0 | system prompt（引擎生成，含工具列表/环境） | 会话内稳定 | 命中 |
| P1 | L0 规则 | 只在改版时变 | 跨会话也命中 |
| P2 | L1 §〇 快照 | 每会话一次 | 只算新内容（其后无历史，不产生重算） |
| P3 | 历史 | 只追加 | 命中 |
| P4 | 当轮动态：检索结果、工具输出 | 每轮 | 只付增量 |

规则一句话：**按稳定性递减排列，只允许尾部追加**。

### 3.3 L0 的三条硬约束

| 约束 | 原因 | 做法 |
|---|---|---|
| 字节稳定 | 任何变化都会让后面全部重算 | 不带时间戳、会话 id、当前状态；首行写 `<!-- L0 v1 -->`，只有改版才变 |
| 位置最前 | 必须排在「每会话会变」的 §〇 之前 | 单独一条 baseline 消息，**不与 §〇 合并** |
| ≤1 KB | 挤占稳定前缀没有收益 | 只写禁止 / 必须，不写知识 |

### 3.4 L1 的三条硬约束

1. 会话开始时注入一次（建会话 seed 消息），之后**冻结**。
2. 会话中途变了 → 追加一条「交接更新」消息，不改写历史。
3. 更省的默认：**留到下次换会话时生效**（§〇 本就是接班用的，不需要中途实时）。

### 3.5 禁止清单

- ❌ 不在会话中途把 §〇 重新拼进上下文（每轮重写 = 每轮全量重算）
- ❌ 不把 L0 塞进 system prompt（工具列表 / 日期 / 插件一变就连坐）
- ❌ 不把任何记忆内容插到历史中间（插入即失效）
- ❌ 不在 L0 里写「当前状态」（那是 §〇 的职责，写了就不再稳定）
- ❌ 不靠模糊的「静态前缀」概念：必须能指出这段在第几条消息、第几个字节开始

### 3.6 成本对照（20 轮会话、上下文 60K）

| 方案 | 计费量 |
|---|---|
| A：L0 + L1 每轮重写 | ≈ 1.2M tokens |
| B：会话开始注入一次 | ≈ 21.2K tokens |

差约 57 倍，且 A 会随上下文变长继续恶化。

### 3.7 落地位置（「命令」场景）

- **L0** → `src/workspace/AGENTS.md`（引擎 `agent-instructions` 当 baseline，首个请求前进入，位置天然最前；`建会话.mjs:42` 默认 cwd 就是 `workspace/`）
- **L1** → `shell/scripts/建会话.mjs:101` 的 seed 消息（把现在的「已读」替换为字段化 §〇 五行）
- **度量** → 每轮看缓存命中率；若某轮骤降，先查「是否有人改写了中部」

## 四、条目格式（v2 的核心）

一条记忆 = 三行：条目行（机器读）+ 两行补充（人读）。

```
- [D-20261120-01] 决策：DSH 引擎端口统一按 3083 处理，脚本不再写死 3080
  证据=shell/scripts/建会话.mjs:57 · 可信=已验证 · 日期=2026-11-20 · 状态=active
  理由：main.js 起的引擎默认 3083；正则写 3080 时取不到 token，面板一直「未连接」
```

### 字段

| 字段 | 取值 | 说明 |
|---|---|---|
| 类型码 | `F` 事实 / `D` 决策 / `P` 偏好 / `L` 教训 / `R` 流程 / `C` 约束 | 决定归属层、检索排序、遗忘策略 |
| 编号 | `类型-YYYYMMDD-NN` | 单条引用。AI 说「按 D-20261120-01」比「你上次说的」可靠 |
| 一句话 | 一个条目只回答一个问题 | 原子性，才可能被 supersede |
| 证据 | `文件:行` / 会话 ref / 命令 | 没有证据就必须标 `推测` |
| 可信 | `已验证` / `待验证` / `推测` | 引用时必须带状态 |
| 日期 | 首次写下的日期，不随后续修改 | 用于遗忘 |
| 状态 | `active` / `superseded→<编号>` / `archived` | 生命周期 |

### 各类型写在哪

| 类型 | 位置 | 只追加？ |
|---|---|---|
| `C` 约束（不碰什么） | §一、职责边界 | 否，可改可删（边界会变） |
| `R` 流程 / `F` 事实 | §二、现状 / 接口 | 否，supersede 更新 |
| `D` 决策 / `L` 教训 | §五、坑与决策 | 是，只追加 + supersede 指针 |
| `P` 偏好 | §二末尾「偏好」小节 | 否 |
| 项目级 `F/D` | `项目记忆/<id>.md` | 视条目，遵循同规则 |

### 硬规则

1. 条目行必须以 `- [` 开头、`]` 结尾前是类型码 + 日期 + 序号，**正则可解析**：`^- \[([FDPLRC])-(\d{8})-(\d{2})\] (.+)$`
2. 一条只回答一个问题。想写两件事 = 两条。
3. 修改已有结论 → 写新条目 + 旧条目改 `状态=superseded→新编号`，**不许直接改旧条目正文**。
4. 补充行最多两行，每行 ≤120 字。
5. 编号在同一天同类型内递增，不复用。

## 五、三条协议

### ① 写入协议（五问，一次 ≤10 行）

1. 是哪一类？（F/D/P/L/R/C）
2. 同主题有没有 `active` 条目？有 → **supersede**，不新增
3. 证据是什么？没有 → 可信度写 `推测`
4. 影响交接吗？影响 → 同一轮改 §〇
5. 会让文件超红线吗？超 → 把最老的 `active` 非决策条目改 `archived` 并移入 `归档/`

### ② 读取协议（两级）

**第一级 · 会话开始注入一次（固定预算 ≈2 KB，随会话冻结）**

```
L0 铁律（≤1 KB，独立一段，永不变）        ← workspace/AGENTS.md，引擎 baseline
+ §〇（≤4 KB，实际应压到 1 KB 内）        ← 建会话 seed 消息
+ _条目索引.md 的 active 条目，最多 30 行   ← 随 §〇 一起注入
```

注入位置与前缀顺序见第三节：**L0 在前、§〇 在后、之后只追加**。会话中途不改这一段。

索引行（工具生成，禁止手写）：

```
- D-20261120-01 决策：端口统一 3083 · 已验证 · 2026-11-20
```

超过 30 条时按「被引用次数 → 日期」排序，其余留在文件里靠检索。

**第二级 · 按需检索**

- 按类型：`§五 里所有 C 和 L`
- 按关键词：编号 / 文件名 / 场景名 / 自然语言片段
- 返回：完整条目（三行）+ 证据，命中的条目「被引用次数 +1」（记在 `_条目索引.md` 的计数列）

### ③ 遗忘协议（三个数字，不靠感觉）

| 数字 | 规则 | 目的 |
|---|---|---|
| **7 天** | §〇 超过 7 天未更新 → 标黄 `⚠ 交接过期` | 防交接腐烂 |
| **30 天** | `active` 且非 `D`、30 天未被引用 → `archived`，移入 `归档/` | 控体量 |
| **3 次** | 被引用 ≥3 次 → 从 §五 晋升到 §二（说明是稳定结构知识） | 让重要的事浮上来 |

`D`（决策）永不自动归档，只被 supersede；`C`（约束）不参与遗忘，只在边界变化时主动改。

## 六、§〇 字段化模板（替换 v1 的四小节）

```markdown
## §〇 当前交接

- 当前：给「命令」场景做记忆层 v2 设计
- 下一步：定 schema → 改 §〇 → 写 5 条真实条目 → 生成索引
- 卡点：等确认是否改现有记忆文件
- 最近变更：2026-11-20 新增 docs/记忆层-v2.md
- 更新时间：2026-11-20 10:40
```

规则：四个内容字段各 ≤3 条；「更新时间」是唯一允许手改的时间戳；整体 ≤4 KB（理想 ≤1 KB）。

## 七、共享层四块板的角色（v2 明确写者）

| 板 | 谁写 | 语义 |
|---|---|---|
| `_跨场景通知.md` | 任意场景，**必须署名 + 日期** | 广播，只读消费 |
| `_待办.md` | 任意场景，写「认领人」 | 可认领的任务 |
| `事实库`（v2 新增） | **唯一归属场景** | 多场景共用的事实只在这里有一份 |
| `_共享记忆/记忆地图.json` + 索引 | **工具生成** | 禁止手改 |

判据：**一条事实只能有一个写入者**。两个场景都要用 → 放事实库，各自引用。

## 八、check 从结构检查升级为语义检查

v1 只查存在性 / 指纹 / 字节数。v2 加八条（全部可用正则 + 文件对比实现）：

| # | 检查 | 判定 |
|---|---|---|
| 1 | 重复主题 | 同类型 + 同关键词（或编号前缀相同）有两条 `active` |
| 2 | 无证据 | `可信=已验证` 但 `证据=` 为空 |
| 3 | 交接过期 | §〇「更新时间」距今 > 7 天 |
| 4 | 死引用 | `superseded→X` 里的 X 不存在 |
| 5 | 状态矛盾 | 同一编号出现两种状态 |
| 6 | 共享层写者冲突 | 两条 `F` 指向同一文件/事实却来自不同场景 |
| 7 | 孤儿条目 | 证据里的路径不存在 |
| 8 | 可信度滥用 | 全篇 `已验证` 但带证据的比例 < 50% |

1、6、7 是真会咬人的——它们对应的正是这套产品最初要解决的两堵墙：**记忆互串**和**记忆造假**。

## 十一、不做的事

- 不做自动摘要 / 向量检索：中文短条目用 grep + 类型码就够，引入 embedding 会让「记忆在哪」变得不可解释。
- 不做跨场景自动合并：合并必须人工确认，否则就是记忆串味的自动化版本。
- 不动 §〇 ≤4 KB 与主文件 ≤25 KB 的红线：v2 只是把「写什么」变严格，不放松体量。
