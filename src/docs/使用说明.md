# 使用说明

## 一、它是什么

一套装在你自己电脑上的 常明：一个「命令」场景、一条常驻 AI 会话、记忆写在本地文件里。
需要你自己的 DSH 引擎——本包**不带引擎**。

## 二、第一次用

```bash
cd shell && npm install && cd ..
./启动.sh            # Linux / macOS；Windows 双击 启动.vbs。端口 3083
```

然后给 AI 面板建会话（标题要和场景里显示的名字逐字一致；`--bind` 会自动把 id 写回场景 json）：

```bash
node shell/scripts/建会话.mjs --title "命令" --bind
node shell/scripts/sessions.mjs --check
```

### 点了启动却「没反应」？

窗口只能有一份（两份会抢同一份 profile，日志里刷 `Failed to open LevelDB ... /LOCK`）。`启动.sh` 的处理顺序：

1. 没有实例在跑 → 直接启动（不会多等）。
2. 有实例在跑 → 等最多 3 秒（你可能刚关掉、它还在收尾；收尾完就接着启动），3 秒后还在跑就把它的窗口提到前台，并打印
   `[启动] 已经在运行（Ns 前还有心跳）—— 已请求把它提到前台`。
3. 进程还在但心跳停了（卡在退出里）→ 自动清理掉再启动；实在清不掉才报错退出，并在终端里留下排查命令。

所以「关掉再点没反应」现在会看到一句话，而不是静默退出。要强制重启：

```bash
pkill -f "electron \." ; rm -f shell/data/.run.lock shell/data/.run.pid shell/data/.run.beat
```

## 三、日常

| 想干什么 | 怎么做 |
|---|---|
| 加场景 | 顶栏标签栏最右点 `＋` 填三个框（推荐）；要自定义布局见「三之二、加一个场景」 |
| 改面板 | 改 `shell/scenarios/<场景>.json`，顶栏 ⟳ 热更新 |

| 出包前自检 | `node tools/发布前检查.mjs` |

## 三之二、加一个场景

一个场景 = 一份布局 json + 一条常驻 AI 会话 + 一张定位卡 + 一份场景记忆。两种加法：

**A. 界面上点 ＋（推荐，30 秒）**

顶栏场景标签最右边的 `＋` → 填「名字 / 英文 id / 一句话说明」→ 创建。它一次做齐五件事：

1. 写 `shell/scenarios/<id>.json`（记忆神经元 + AI 会话面板，AI 面板已钉到新会话）
2. 建常驻 AI 会话，并把 `sessionId` 回写到面板（等价 `建会话.mjs --bind`）
3. 建 `data/.dsh/场景记忆/<名字>/` 五件套（`场景记忆.mjs init`）
4. 在 `_场景身份索引.md` 表格里登记一行
5. 写 `<id>-context.md` 定位卡骨架（待你补「管什么/不碰什么」）

完成后点「**打开这个场景**」标签立刻挂到顶栏。英文 id 用小写字母/数字/连字符（如 `translate`）；
建 AI 会话这步要等引擎回话（约 20 秒），失败会在弹窗里给出原因，且不会清掉已写到一半的文件。

**B. 命令行四步（要自定义面板布局时用）**

**1. 抄模板改布局**

```bash
cp shell/scenarios/_模板-新场景.json shell/scenarios/translate.json
```

改这几项就够：`id`（= 文件名，小写字母）、`name`（显示名）、`description`（一句话，写在场景切换处）、
`panels[].title`、AI 面板的 `sessionTitle` 与 `pinTarget`（都填显示名）。

面板 `type` 决定渲染器（`renderer/renderers.js` 里的 `renderers.<type>`）：
`neuron` 记忆神经元、`harness` AI 会话、`embed`/`web` 网页、`file` 文件、`log` 日志、
`chart` 图表、`flow` 流程、`board` 看板、`dash` 总览……写错类型 = 面板空白。
每个面板的 `col/row/w/h` 是 12 列网格里的位置（`w` 3 + `w` 1 = 4 列，正好左大右窄）。

**2. 建会话并回写 id**

```bash
node shell/scripts/建会话.mjs --title "翻译" --bind --scene translate
```

`--bind` 会把 `sessionId` 写进 `scenarios/translate.json`（只改值、不重排 json），不用手抄。
标题必须和 json 里的 `sessionTitle` 逐字一致，否则 AI 面板找不到会话。

**3. 定位卡 + 记忆骨架**

```bash
node tools/场景记忆.mjs init  --场景 翻译     # 建 data/.dsh/场景记忆/翻译/ 四件套
node tools/场景记忆.mjs stamp --场景 翻译     # 生成 身份卡.md / 场景画像.md
```

再手写 `shell/scenarios/translate-context.md`（定位卡，四行就够）：这个场景一句话是干什么的、管什么、
**不碰**什么、记忆与面板路径。这张卡会随场景注入给 AI，写清楚边界比写长更有用。

**4. 登记 + 自检**

- `shell/scenarios/_场景身份索引.md` 加一行（场景 id / 面板 id / 会话名 / 会话 id / 定位卡）
- 想要自己的图标：在 `renderer/renderer.js` 的 `ICONS` 里加 `'translate': '🧩'`（或 png 路径）；
  不加也能用，只是退回默认 🧩（`check-gui.mjs` 会给一条 warning 提醒）
- 顶栏 ⟳（或重启）→ 左上角出现新的场景标签
- 验收：`node shell/scripts/sessions.mjs --check`（每个 AI 面板都能对上会话）、
  `node shell/scripts/check-gui.mjs`（结构契约）、`node tools/场景记忆.mjs list`（记忆五件套齐）

> `first: true` 只留给默认场景：启动时它排在最前。新增场景不要带这一项。

## 四、记忆怎么用

- 每个场景的 AI 干完活，让它把结论写进该场景的 `场景私有记忆.md`
- 收工/换会话前：`node tools/场景记忆.mjs 交接 --场景 <名字>`（归档旧版 + 补 §〇）
- 想确认没写坏：`node tools/场景记忆.mjs check --场景 <名字>`
- 看所有场景状态：`node tools/场景记忆.mjs list`

## 五、常见问题

| 现象 | 处理 |
|---|---|
| 启动提示没装依赖 | 先 `cd shell && npm install` |
| 启动后停在引擎页 | 点顶栏的场景标签；或等几秒它会自动进「命令」 |
| 面板空白 | 顶栏 ⟳ 刷新；再不行看 `shell/server.log` |
| 端口被占 | 改 `shell/main.js` 顶部 `DSH_PORT`（默认 3083） |
| 记忆面板 0 个区域 | 用 `启动.sh` / `启动.vbs` 启动，别直接 `electron .` |
| 想换引擎位置 | 让 `engine/` 指向你的 DSH 引擎目录（软链/junction） |

## 六、把网页版 AI 当接口用（0 API token）

顶栏那 5 个站（DeepSeek / 豆包 / 千问 / 智谱 / Kimi）不是只能手点：壳里带了一个本地 HTTP 桥，
任何会话、脚本都能直接问，**用的是你手动登录的那份 cookie**，不花 API token。

```bash
cd src
node tools/webai.mjs list                     # 有哪些站、桥在不在
node tools/webai.mjs ask kimi "用一句话解释向量数据库"
node tools/webai.mjs ask tongyi --file 需求.md --out out/    # 长问题走文件，长回答落盘只回预览
node tools/webai.mjs state                    # 现在有没有任务在跑
```

底层就是四个端点（只在 127.0.0.1:31239，不对外）：

| 端点 | 用途 |
|---|---|
| `GET /webai/keys` | 站点清单 |
| `GET /webai/state` | 在跑的任务 |
| `GET /webai/who` | 哪个窗口在接活、桥版本 |
| `POST /webai/ask` | `{"key":"kimi","text":"…","timeoutMs":180000}` → `{ok,text,elapsedMs}` |

用之前得知道它的脾气：

- **一次只问一个站**（串行）。并发会互相抢输入框，比慢更糟。
- **必须先在顶栏那个窗口里登录**；没登录/要过验证码时它会把现场（输入框、按钮、页面尾部）一起带回来，不会假装成功。
- 回答是**读页面文字**得来的，站点改版就可能读歪 ⇒ 它做了"判有没有开始答、判答完没有、切掉推荐追问"的启发式，但**不适合要求 100% 稳定的流水线**，更别拿它做需要严格 JSON 输出的环节。
- 站点会限流/排队；商用条款也各有限制 —— 自用省钱可以，别转卖成产品。

### 六之二、让 AI 面板**直接调用**网页版（MCP）

上面那套是"脚本问站"。如果想让面板里的 AI 自己判断"这题该问一下 DeepSeek 网页版"，
就把它包成 MCP 工具 —— 引擎的 `@deepseek-ai/dsh-mcp-client` 会把外部 MCP server 的工具
注册进模型的工具表，名字形如 `mcp__webai_deepseek__ask`。

已经接好了 4 个站（DeepSeek / 豆包 / 千问 / 智谱；Kimi 因为打不进输入框先不接）：

| 位置 | 是什么 |
|---|---|
| `src/mcp/webai-mcp.mjs` | stdio MCP server（零依赖），一个进程服务一个站，只暴露 1 个工具 `ask` |
| `data/.dsh/profiles/web/cordis.patch.yml` | 4 条 `mcp-webai-*` 条目，`config.serverName/transport/command/args` |
| 右上角「MCP」面板 | 能看到哪几个真挂了（标「已挂载」）、每轮固定开销多少，可逐个开关 |

开/关就是面板里点一下（写 `disabled: true`，引擎热重载）。命令行增删就是编辑那段 YAML：
一条 `id` + `name: "@deepseek-ai/dsh-mcp-client"` + `config`（`serverName` 只能 `[A-Za-z0-9_-]`）。

验证它真的挂上了（不用配模型 key）：

```bash
cd src
node mcp/webai-mcp.mjs --site deepseek        # 手动喂一行 initialize 也行，但更简单的是看启动日志
grep "webai-mcp" shell/server.log | tail      # 出现「握手：客户端 dsh-mcp-client」+「要工具表（1 个）」= 挂上了
```

脾气（和上面那套一样，别抱幻想）：

- **没有流式**，慢站一次 10–60 秒；一次只能问一个站（串行）。
- 模型看到的只是"一个名叫 ask 的工具"，它**看不到**网页版的登录态/验证码 → 报错信息会原样带回给它。
- 回答超过 1.2 万字会截断并提示模型改用 `node tools/webai.mjs ... --out 目录/` 落盘。
- 每个挂着的 MCP 每轮都吃固定 token（4 个约 520/轮）；用不上的在面板里关掉。

## 七、边界

- 不含引擎、密钥、任何真实用户数据
- 记忆/会话都在你本机，不上传
